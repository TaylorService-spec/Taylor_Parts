## Notes on cells marked UNKNOWN

- **Frontend `access/` layer liveness (row 6):** needs a "who imports this" trace across all 38
  files before any file in that directory is scheduled for change or deletion.
- **Employee field-level writer split (row 7):** needs a field-by-field reconciliation between the
  legacy Firestore `employees/{employeeId}` schema and the three PostgreSQL Employee migrations to
  determine, per field, which store is actually authoritative today. This is upstream of building
  the "governed Employee create/update writer" the roadmap calls for.
- **Employee<->Principal link writer (row 8):** not located this pass; needed for a complete Phase B
  picture even though the read side is fully built.
- **Work Order assignment (row 10):** intentionally left as "blocked, do not start independently" --
  this matches the existing repo ruling (Owner ruling H) and PR #1915's own disposition in the
  reconciliation roadmap ("KEEP AS DESIGN INPUT... do not implement independently of Work Order
  cutover"). Recorded here as confirmation, not a new finding.

## Conflicts found

**None found that meet the "mutually exclusive claims over the same fact" bar.** The
Firestore-era and PostgreSQL-era authorities inventoried here are largely **sequential**
(PostgreSQL is additive/parallel, not yet contradicting Firestore for the same field) rather than
**concurrent conflicting writers** -- consistent with the "no broad dual-write" rule in
`2026-09-16-parallel-v2-sandbox-cutover-strategy.md` §5. The one area this pass could not fully
clear is the Employee field-level split (row 7) -- flagged as UNKNOWN rather than asserted safe.
