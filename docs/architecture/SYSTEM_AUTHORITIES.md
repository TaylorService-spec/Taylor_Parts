# System Authorities

A quick-reference map of "who owns what" — not a replacement for the ADRs (`docs/architecture/ADR-*.md`), which explain *why*; this is just a fast answer to "where should I change this?" so a human or an AI assistant doesn't have to rediscover it (or worse, build a second, competing implementation because the first one wasn't found).

**Verify before trusting.** This doc is hand-maintained and can drift, the same way any doc can (see `CLAUDE_CONTEXT.md`'s intro paragraph and rule 9 for two concrete times a doc/spec claimed something that wasn't true in code). If a row here disagrees with what you find in the actual file, the code wins — update this table to match, don't assume the table is right and the code is wrong.

| Work Order lifecycle (state machine + permissions) | `functions/src/transitionEngine.ts` (canonical), mirrored client-side in `domain/workOrderWorkflow.js`. **ND-18 (Owner ruling 2026-08-27) admitted the first and only REVERSE edge:** `SCHEDULED → READY_TO_DISPATCH`, via the `Unschedule` action, admin/dispatcher, reason required. It is legal from `SCHEDULED` and nowhere else — once a technician has been dispatched the job is committed. Because `MarkReady` and `Unschedule` now share a target status, the transition edge alone no longer identifies which action is legal, so a third table — `ACTION_ALLOWED_FROM` — is part of the contract and must be mirrored client-side with the other two. Any further reverse edge is its own decision and may not appeal to this one |
| **Scheduling authority** (ND-18 – ND-22, Owner ruling 2026-08-27) | Split by whether a change touches the lifecycle. **Un-scheduling IS a lifecycle transition** and lives in `functions/src/transitionWorkOrder.ts` as the `Unschedule` action — it clears the scheduling projection and stages an `unscheduleWorkOrder` Audit Event carrying the technician and window given up, in the same transaction. **Re-timing and reassignment are NOT** — they rewrite Planning fields under an unchanged `SCHEDULED` status and live in `functions/src/scheduling/schedulingCommands.ts` (`rescheduleWorkOrder`, `reassignScheduledWorkOrder`), each staging its own Audit Event with the prior technician and window.
