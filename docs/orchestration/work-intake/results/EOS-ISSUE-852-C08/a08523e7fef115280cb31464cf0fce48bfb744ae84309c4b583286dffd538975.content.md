## EOS-ISSUE-852-C08 — Sector 08: Agent Manager concurrency/dedup/throttle/retry

**Scope**: `docs/orchestration/lib/agentManager.mjs` (read-only analysis, no repo writes — matching how sibling sectors C05/C06/C07 handled `READ_ONLY_ANALYSIS`; this response is the deliverable, a separate write-back process persists it).

### Findings

**1. MEDIUM — `findEquivalentResult()` dedup guard fails open when only one side declares a freshness anchor**
`docs/orchestration/lib/agentManager.mjs:30-38`:
```js
if (request.freshnessAnchor && r.freshnessAnchor && request.freshnessAnchor !== r.freshnessAnchor) return false;
```
This only rejects reuse when **both** sides carry a `freshnessAnchor` and they differ. If the new request declares an anchor (e.g. "must be fresh as of commit X") but the candidate result has none, or vice versa, the mismatch check is silently skipped and the stale/undated result is treated as equivalent → `DEDUPE_REUSE`. The intended guarantee ("avoid reruns when nothing changed, §6" — comment at line 27-29) only holds when producer and consumer both consistently populate the field; nothing in this module enforces that. `agentManager.test.mjs` has no test exercising the mixed-declaration case (only the same-fingerprint/no-anchor path at lines 107-114), so this gap is untested. This corroborates and independently re-verifies the same finding surfaced in the EOS-ISSUE-852 sector consolidation.
→ Fix: treat a missing anchor on either side as "cannot prove freshness" and fail closed (no reuse), not fail open.

**2. MEDIUM — `planIntegrationBacklog()`'s overlap detection is weaker than the sibling concurrency-safety logic in the same file, and untested for the gap**
Two different "do these paths overlap" implementations coexist in this one file:
- `pathsOverlap()` (`agentManager.mjs:79-81`), used by `planConcurrentWriteSectors` for dispatch-time wave partitioning: normalizes paths first (`normalizePath`, line 73-75: backslash→`/`, strips `./`, collapses slashes) and treats directory containment as overlap (`src/foo` ∋ `src/foo/bar.js`).
- `pathOverlap()` (`agentManager.mjs:251`), used by `planIntegrationBacklog` for integration-ordering conflict detection (lines 277-279, 292): `a.paths.filter((path) => b.paths.includes(path))` — **raw strict-equality array intersection, no normalization, no directory-containment check.**

Consequence: two integration-backlog items that touch the same file but spell the path differently (`./src/a.ts` vs `src\a.ts`), or one item scoped to a directory and another to a file inside it, will **not** be recognized as conflicting by `planIntegrationBacklog`. They won't be forced adjacent, `overlappingPaths` won't record the collision, and `nextByTarget` won't serialize them — exactly the "fratricide" scenario `planConcurrentWriteSectors` was explicitly hardened against (see its test comment at `agentManager.test.mjs:254`, "the #826/#827 case"). `agentManager.test.mjs:163-172` only exercises exact-identical path strings for `planIntegrationBacklog`, so this asymmetry has no regression coverage.
→ Fix: route `planIntegrationBacklog`'s conflict/overlap checks through the same `normalizePath`/`pathsOverlap` pair `planConcurrentWriteSectors` already uses, so both "is this safe to run/integrate concurrently" checks in the module agree.
