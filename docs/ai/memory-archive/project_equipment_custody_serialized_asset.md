Inventory-lane P0 Specification for the Serialized Asset ↔ Equipment installation handoff + Available/Customer Equipment composition. Base main 364a8b4. **Rev 6 reached FINAL PASS (technical clearance only; NOT committed, no PR/impl authority).**

Core governance model (do not regress — earlier drafts were rejected for these):
- **Two separate authorities**: Serialized Asset (Enterprise Inventory §4.9 = persistent inventory identity for SERIAL-tracked Parts) vs Equipment (ADR-006 = installed/customer-serviceable asset). Installation LINKS them; never merge, never broaden equipment/{id} into an inventory record.
- **No parallel ledger/collection**: movement is the single EI ledger (inventory_transactions generalized, invariants 1-2) + Transfer Orders (§4.5) + Location tree (§3.1: WAREHOUSE/BIN/MOBILE-truck/VENDOR/CUSTOMER/VIRTUAL-in-transit). Trucks = MOBILE locations (adopted EI **Phase 4**), NOT a vehicles/{id} authority (optional future Vehicle business record LINKS to a MOBILE location). REMOVED from earlier revs: equipment_movements, equipment_fulfillment_events, vehicles/{id}, custody union on Equipment, pre-install fulfillmentState on Equipment, COMPANY pre-install Equipment records.
- **Installation handoff (§H)**: delivery = prior governed Transfer to CUSTOMER location; installation = ONE atomic command posting a single CONSUMED/installed effect + set Serialized Asset INSTALLED/non-available + create/link Equipment + append audit (all-or-nothing; never both installed AND available). Nullable `currentEquipmentId` (single-valued) + immutable append-only installation-link history → one Equipment↔one serial, SEQUENTIAL redeploy after repair (new Equipment record each install), never concurrent. Replacement retires old Equipment + creates new + REPLACES/REPLACED_BY (no serial re-attach; reusable "installation position" = future entity).
- **Business boundaries**: Part Master ≈36k catalog membership ≠ stock (stock only via governed ledger/location); Parts Town = external Supplier, Phoenix = supplier fulfillment loc not a Warehouse, supplier availability ≠ on-hand until governed Receiving; identifier confidentiality (ADR-008): customer output exposes internalPartNumber as the ONLY part identifier (description/qty ok), never supplier name/id/SKU/URL/cost/xref, manufacturer PN default-hidden, enforced by backend projections+permissions + tests. No UD-3/quantity redefinition.
- Phasing aligned to adopted EI plan (Phase 1 ledger+Part Master ADR-008; Phase 2 Receiving; Phase 4 Transfers+trucks); this Spec adds serial↔equipment handoff + Available/Customer/timeline composition on top.
