1eShared system vs North Star — what is reused, what is designed
Reused platform (Lists P1 + existing EOS)
  • List engine: listViewDefinition columns/filters/sort/savedViews, readVia, capabilityRequirement
  • State engine: pipeline views from opportunityLifecycle (Open · Mine · Needs Attention · At Decision · Won · Lost · All) with truthful counts
  • Search, Filter sheet (governed stage words as checkboxes), sort, Columns, saved-view capture
  • Row navigation: row = anchor; cmd/middle-click work; checkbox/overflow stop propagation
  • 16-state UI system; record-count + result-context logic; pagination; responsive column-drop order
  • Attention derivation (deriveAttention: Awaiting decision / No next action / Close overdue) — presentation of existing projections only
North Star customization (this design)
  • Full object-family header: context line, rule pair, serif title, count sentence, Create Opportunity placement
  • Opportunity row composition: reference + need identity, customer + channel, stage words + n of 6, tone-colored attention, bare tabular value, close with proximity/overdue tone
  • Agreement / Order column: SA reference + state word over SO reference or "Order not created"; "No agreement" when none — compact context only, no agreement workflow here
  • Opportunity wording for all five designed states (1d)
  • Responsive recomposition: 768 three-line identity fold; 375 purpose-built scan cards
Authority gaps (named, not invented)
  • G1 — No "Opportunity Name" field. Identity is the governed reference + the need subtitle. A name field is a product decision, not a design one.
  • G2 — Agreement reference is not on the opportunity list read. The association lives on the agreement (sourceOpportunityId); getSalesAgreementForOpportunity is per-record. The column needs list-level resolution (or denormalization) to populate; until then it renders "No agreement" / "—" truthfully. Environment gate off (NOT_ENABLED) → the column is omitted entirely, never dead cells.
  • G3 — Sales Order reference is durable on the record after atomic Won (closeOpportunityAsWon) — LIVE for Won rows; for open rows with an agreement-created order it depends on G2's resolution.
  • G4 — Customer name resolution (existing O2): the read returns accountNameById: {} today; rows render "Customer — name unavailable" until it ships. Demo names are design intent.
  • G5 — No governed currency on expectedValue (existing O1): bare numbers stand; "Not estimated" when absent.
