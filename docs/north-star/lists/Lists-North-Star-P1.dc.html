Master grammar. Identity is two lines (reference bold + subject muted); Account/Location likewise. Object state and attention are SEPARATE columns — "Scheduled" is where the record is, "Overdue 2d" is why a human should look; words carry the meaning, tone color reinforces, no pills. Row 1 shows hover/focus fill. Views are operational lenses (understated tabs, active = bronze underline), filters are removable tokens with Clear all, result context explains why the list changed. Counts and states here are sample content — implementation reads each object's own governed projections.

B · Initial loading. Title + views render; toolbar disabled; 8 row skeletons in the table region. Never a lone centered spinner.
C · Background refresh. Rows stay; “Refreshing…” replaces “Updated moments ago” in the utility line. The table never blanks.
D · True empty. Serif “No work orders yet” + what this workspace will hold. Create button only when the user truly may; otherwise no CTA at all.
E · Empty saved view. “No work orders need attention.” + “Nothing is in this view right now — see Open (32).” Reads as good news, not missing data.
F · No search results. “No results for ‘Taylor C713’.” + Clear search / adjust filters. No create CTA here.
G · Filters return zero. “No work orders match these filters.” Active tokens stay visible above; Clear filters is the action. Distinct from D and F.
H · Load error. “Work orders could not be loaded.” + Try again. Header + toolbar stay; no raw backend text ever.
I · Degraded. Rows load; a quiet line above the table: “Assignment names are temporarily unavailable” — those cells say “Name unavailable”, everything else works.
J · Access restricted. “Access restricted — your current access doesn’t include this workspace.” No counts, no columns, no request-implies-grant.
K · Offline / stale. Utility line: “Offline · Showing last available data.” Rows stay readable; freshness never claims live.
L · Large set. “1,248 work orders” · footer “1–50 of 1,248 · Previous / Next”. Same composition, no layout change.
M · Single record. “1 of 148 work orders” + the one row. The table grammar holds; no apologetic empty styling.
N · Selection mode. Checked rows tint stone; a bulk bar docks above the table: “4 selected · Assign · Export · More · ✕”. Only governed bulk actions appear.
O · Action in progress. Bulk bar shows “Assigning 4…”; its buttons disable; rows stay visible. No blocking modal unless the action truly requires it.
P · Action failure. “2 of 4 could not be assigned.” Failed rows keep an exception marker; Retry failed; success is never implied.
Q · Action success. One quiet confirmation line; the updated row states are the real feedback. No celebration screens.
