2dShared page-state system — 17 UI states, one rendering each. The shell (rule pair, title, views) survives every state; counts render only on a settled read.
IDLE. Required identity/context not ready; the read has not begun. Distinct from Loading — the page states nothing rather than a spinner about a request that does not exist.
LOADING. The read is occurring: skeleton rows in the intact shell. Never a lone spinner; no layout shift on arrival.
POPULATED. The anatomy above.
TRUE EMPTY. "No work orders yet." + purpose sentence; Create only when truly permitted.
EMPTY VIEW. "No work orders need attention." — the view's own sentence + a link to a useful view. Records exist; this slice is empty.
SEARCH ZERO. "No results for 'Taylor C713'." — query echoed, Clear search; scope stated (this searched the loaded view / a number-prefix query); no create CTA.
FILTER ZERO. "No work orders match these filters." Tokens stay visible — the cause is on screen; Clear filters. States how many rows are being narrowed to none.
UNKNOWN / UNRESOLVED. "EOS cannot determine which work orders are assigned to you." The view says so and renders NO count. Unknown is not zero.
NOT ENABLED. The feature/read is not active: one sentence, once. Distinct from Denied — and the column/section it would feed is omitted, never dead cells.
DENIED. "This workspace is not available to you." + who to ask. No counts, no views, no create — nothing leaks. Fail-closed.
UNAVAILABLE. "Work orders could not be loaded. Your work elsewhere is unaffected." + Try again. No raw backend text.
DEGRADED / PARTIAL. The list renders; the failed secondary fact says so per cell ("Name unavailable") with one quiet line above the table. Never the document id as a fallback label.
OFFLINE / STALE. Only where retained data genuinely exists (handheld sync queue): "Offline · showing last available data." Never claimed elsewhere.
SELECTION MODE. Only where governed bulk actions exist: tinted rows + docked bar "4 selected · [governed actions] · ✕".
ACTION IN PROGRESS. The bar shows progress; controls disable; no blocking modal.
ACTION FAILURE. "2 of 4 could not be assigned" — failed rows stay marked, Retry failed; success never implied.
ACTION SUCCESS. One quiet line; the updated row state is the real confirmation.

TRUE EMPTY / EMPTY VIEW / SEARCH ZERO / FILTER ZERO / UNKNOWN / DENIED / UNAVAILABLE are seven different facts with seven different sentences and seven different ways out — never one generic empty component.

2eObject state · Attention · UI state — never collapsed
Object state — the governed lifecycle position
Closed · Quoting · Dispatched · Won · Waiting for parts · Cancelled
Words from the object's own vocabulary, never enums, never color alone, no pills. Tone families (muted/info/active/positive/warning/exception) are presentation over governed states — the state is never renamed. Each family's set comes from its own domain; there is no universal workflow taxonomy.
Attention — a derived condition, its own column
Close overdue 6d · No next action · Below reorder point · —
Domain-derived only, worded by the domain's own projection; often the reason a user opens the record, so it gets first-class position — never forced into the State column, never buried in overflow, never a score. Not every object has attention logic; where none exists the column does not.
UI state — the interface itself (2d)
All three coexist: a row can be "Waiting for parts" (object) + "Overdue 2d" (attention) while the page is in background-refresh (UI). Each renders in its own place.
2fRow hierarchy & responsive drop/fold priority
Row priority (order varies per object; the discipline does not)
  1. Identity — governed reference bold 13.5 + human subtitle muted 12.5 (two lines max)
  2. Object state — words + tone
  3. Attention / exception — where the object derives one
  4. Primary context — the resolved related name (account, location)
  5. Assignment / ownership — Unassigned ≠ Unresolved
  6. Critical timing — overdue in exception tone; "Not recorded" honestly
  7. Numeric / commercial — right-aligned tabular Inter; currency only where governed
  8. Secondary metadata / relationships — the five projection treatments (2a)
Responsive behavior

Columns leave in reverse priority: 8 → 7 → 6 → 5 first. At 768 keep identity / state / attention / one timing-or-context column; drop before fold — at most one secondary line folds into identity. At 375/320 recompose as the structured row (2c). 32px working density on desktop (up to 44–52px where two-line identities need it); ≥44px targets wherever touch is the interaction context. Never centered data, never a card per record, never decorative icons per cell.

Shared grammar this page proves
Complete collection read → no pagination controls at all. Governed operational order (attention first, then closing soonest) → Pattern A: no sort control, no column chooser. Search/stage narrowing run over loaded rows only; result denominator = the view. My Opportunities renders no count when the viewer's employee identity cannot be resolved. Create renders protected + reason when write-readiness is off — visible text, not a vanished button. Relationship column states existence only ("Agreement" / "Order created") — ids are projected, references are not, and no per-row read prettifies a scanning surface.
Opportunity domain — not EOS-wide concepts
The six sales stages and "n of 6" position; expected close and its 14-day proximity note; expectedValue's bare-number rule (G5 — no governed currency); the pipeline view set; deriveAttention's four reasons; agreement/order lineage; owner-as-salesperson semantics. None of these may leak into another family's list as a default.

Parts domain — and its inviolables
On hand ≠ Available — no Available column exists anywhere (no availability authority). On hand is the governed BASELINE and shows its provenance rather than hiding it. Demand is planned, never reserved. Serialized units are assets, not quantity. The list implies no operational effect: counting doesn't adjust, picking doesn't reserve, scanning doesn't move stock. 2lShared component board — conceptual mapping onto existing EOS layers
Page structure
WorkspaceIdentity (exists — crumb, rule pair, serif title + count, summary line, action slot) · context line · primary action in its three treatments (Button variants primary / protected-with-reason).
Views
Radio-semantics view row (role="radiogroup"): active = 3px bronze underline; count inline; exception count in tone; null count renders nothing; status-group chips (FilterBar) for grouped-status families.
Narrowing
Search input (scope-naming placeholder) · Filter trigger with active count · governed-vocabulary filter sheet / AddFilter from the definition · active tokens (ActiveCriteria) + Clear all · dropped/refused-criteria notice.
Record row
Anchor-deferring row (real link in the identity cell; tr defers to it) · two-line identity · StateLabel (words + 6 tone families) · AttentionSignal · assignment (Unassigned ≠ Unresolved) · timing with overdue tone · numeric right/tabular · relationship in its five projection treatments.
Feedback
HonestState (exists) carrying the 17-state vocabulary · result context sentence · synthetic-data note · per-cell degraded fallbacks.
Data shape
Complete-read footer (nothing) · cursor Load more · governed aggregate total (useListViewChrome — null over 0) · definition-declared saved views (ListViewHeader).

These compose the existing behavioral layers — each object's listViewDefinition (columns, filters, savedViews, sort, capabilityRequirement, readVia), its domain view model (views, empty texts, tone vocabulary, attention projections) and fail-closed capability gating. The board replaces none of them.
